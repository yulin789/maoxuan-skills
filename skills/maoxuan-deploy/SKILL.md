# 一般号召与个别指导：让决定真正落地

## R — 原文 (Reading)

> 「任何领导人员，凡不从下级个别单位的个别人员、个别事件取得具体经验者，必不能向一切单位作普遍的指导。」
>
> 「将群众的意见（分散的无系统的意见）集中起来（经过研究，化为集中的系统的意见），又到群众中去作宣传解释，化为群众的意见，使群众坚持下去，见之于行动，并在群众行动中考验这些意见是否正确。」
>
> — 毛泽东，《关于领导方法的若干问题》（1943，第3卷 p527-528）

---

## I — 方法论骨架 (Interpretation)

"发了通知就算部署"是最常见的错。通知只能动员，无法检验自己是否正确。作者的原话是：只作一般号召而无个别指导，"就有使一般号召归于落空的危险"。

所以落地是两步而不是一步：先发一般号召（总目标、总要求），再在附近选二三个单位**深入做**，详细了解过程，也详细了解其中若干具体人的经历与表现。从点上拿到的不是"成功案例"，而是"哪里卡住、怎么卡住"的具体经验。用这些经验回来修改号召，再拿到更多单位去考验。

第三件事是纪律：一定时间只能有一个中心工作，其余排第二、第三位；向下传达必须经过该项工作的下级总负责人（作者称之为"一元化"），不能让对口部门知道而总负责人不知道、不负责；决定一旦作出就"坚持地贯彻下去，务必得到一定的结果"。

循环的另一半是"从群众中来，到群众中去"：分散意见→研究集中→回到群众宣传解释→行动中检验→再集中。检验发生在行动里，所以每一轮都带回新信息；作者说"一次比一次地更正确、更生动、更丰富"。

## A1 — 应用示例 (Application Example)

### 示例 1: 一九四二年整风——有成绩与没成绩的差别
- **类型与来源**: 原书案例（c10；《关于领导方法的若干问题》第3卷 p528-529）
- **问题/输入**: 同一套整风要求下发到各根据地，执行效果差异极大。
- **方法论的使用**: 作者逐类对比：有成绩的，都是把一般号召与个别指导结合起来——先在一两个单位突破，取得具体经验，再普遍推开；没成绩的，三种情形——不团结积极分子组成核心（领导成了官僚主义）、不总结群众经验而自作聪明（空论）、满足于一般号召不做个别指导（号召停在嘴上、纸上、会议上）。
- **结论**: 差别不在决心大小，而在有没有"点上突破→总结经验→再推广"这一环。
- **结果**: 原书明确给出这一归因；各单位的具体过程未逐项叙述。

### 示例 2: 试验田与抓两头带中间
- **类型与来源**: 原书案例/方法（f28；《工作方法六十条（草案）》第6卷 p1198-1199）
- **问题/输入**: 推广一项新做法（如新耕作法、新工艺），开会发文件后下面不动。
- **方法论的使用**: 先办试验田（乡村办试验田，城市抓先进厂矿、车间），"突破一点就可以推动全面"；再组织参观与展览，让干部实地看；用相同条件下的先进与落后作比较；抓两头、带中间——"中间的状态又总是占多数，抓住两头就把中间带动起来了"。
- **结论**: 示范替代命令，比较替代讲道理。
- **结果**: 原书给出方法与典型场景；推广后的量化效果未说明。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 制度/流程/新工具已经全员通知，两周后只有一两个部门在照做。
2. 老板说"这事必须推下去"，但下面反馈"不知道具体怎么做"。
3. 有一个试点成功经验，想全面推广，但担心推歪了收不回来。
4. 多个部门同时被布置了互相冲突的任务，都在等对方。
5. 决定已经做出，但执行中不断走样，且没人对结果负责。

### 语言信号 (用户的话里出现这些就应激活)

- "通知已经发了，但没人动" / "we announced it, nothing happened"
- "推不动" / "can't get traction"
- "先试点再推广" / "pilot then scale"
- "落地" / "execution gap"
- "到底谁负责" / "who owns this"

### 与相邻 skill 的区分

- 与 `maoxuan-priority` 的区别：priority 决定推哪一个，本 skill 决定怎么把它推下去（含中心工作排序这条纪律）。
- 与 `maoxuan-team` 的区别：team 管班子的议事与运行规则，本 skill 管"决定从会议室走到一线"的路径。
- 与普通"变革管理"框架的区别：本 skill 强制"点上突破→总结→改号召→再推广"的次序，并要求指明一元化传达人；不产出沟通计划书。

## E — 可执行步骤 (Execution)

**必需输入**：① 要推开的做法（一句话）；② 可及的候选试点单位（≥3 个）；③ 该项工作的下级总负责人姓名；④ 检查频次与评比口径。
**缺失时询问**：若没有"总负责人"（只有对口部门），先补这一项，否则执行必然绕过责任链。

**交付物与完成标准**：一份落地单——一般号召（目标+范围+时限）／试点名单（2–3 个，注明为什么选）／试点记录（卡点清单）／修订后的做法／推广批次／检查时点／一元化传达人。

1. **写一般号召**
   - 完成标准：一段话说清"要什么、到什么程度、什么时候"，不写方法细节（方法由试点产出）。
2. **选点（2–3 个，不要多）**
   - 完成标准：至少包含一个"愿意做"和一个"抵触"的单位；写明选点理由与两点的差异。
3. **亲自指导并记录过程**
   - 完成标准：记录的是"第几天卡在哪、谁提出什么反对、怎么处理"，不是最终成果汇报。
   - 判停条件：若试点单位被特殊照顾（额外资源/额外人手），标注"经验不可直接移植"。
4. **总结出可复制的做法**
   - 完成标准：≤5 条，每条是动作而非原则（如"会前 24h 交一页纸"而不是"要重视准备"）。
5. **用新做法重发号召**
   - 完成标准：修订版号召里能看到至少 2 处来自试点的改动。
6. **分批推广 + 检查**
   - 完成标准：给出批次与每批的检查时点；检查项目含"是否按新做法执行"与"执行后结果如何"两类。
7. **落实三条纪律**
   - 完成标准：中心工作唯一且已排序；传达经过总负责人；对已作决定写明"必须得到什么结果"。
8. **收口**
   - 完成标准：一轮结束后写出"下一轮要改什么"，循环回到第 3 步。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 决定本身还没定（还在讨论要不要做）：此时应先用 `maoxuan-priority` 或 `maoxuan-team`。
- 一次性、不可重复的事务（如搬家、一次性上线）：试点成本高于收益，直接做并设检查点。
- 试点单位与推广对象差异过大（资源、人群、地域完全不同）：经验不可移植，应改为"多点多轮小步推"。

### 作者在书中警告的失败模式

- **只作一般号召而无个别指导**（x10）："就有使一般号召归于落空的危险"。
- **不团结积极分子组成核心**（x11）：领导变成脱离群众的官僚主义。
- **绕过总负责人**（x13）：上级部门对口找下级部门，总负责人不知道、不负责。
- **只提任务不解决方法**（x15）："过河要有桥或船"，任务只是一句空话。
- **只管任务不管群众生活**（x14）：会议开不成，任务也完不成。
- **抓而不紧**（x16）："抓而不紧，等于不抓。"

### 作者的盲点 / 时代局限

- 原文的推广对象是相对同质的根据地与单位；现代组织里试点与推广对象差异大，需要额外做"可比性检查"，原文未给方法。
- "一元化"在权力集中、信息透明的组织里有效；在矩阵式组织中，绕过职能线的传达会引发新的冲突。使用时需明确"总负责人"是结果负责人而不是职能上级。
- 作者假定试点会得到真实反馈；当试点成为"政绩工程"时，反馈会被美化。需要独立观察渠道（可用 `maoxuan-investigate` 的 f42 手段）。

### 容易混淆的邻近方法论

- 与"PDCA 循环"不同：PDCA 是通用改进环，本 skill 的重心在"号召—试点—改号召"的政治/组织过程，尤其强调一元化与中心工作唯一。
- 与"敏捷迭代"不同：敏捷以产品增量为中心，本 skill 以"做法能否被复制"为中心。
