# 定期综合报告制度：把"请示报告"参数化

## R — 原文 (Reading)

> 「为了及时反映情况，使中央有可能在事先或事后帮助各地不犯或少犯错误，争取革命战争更加伟大的胜利起见，从今年起，规定如下的报告制度。」
>
> 「必须改正对上级事前不请示、事后不报告的不良习惯。」
>
> — 毛泽东，《关于建立报告制度》（1948，第4卷 p734-735）

---

## I — 方法论骨架 (Interpretation)

这份文件的价值不在"要向上级汇报"这个常识，而在把汇报**参数化**到可以直接照抄的程度：

**谁写**——各中央局、分局书记自己动手，"不要秘书代劳"。理由是：只有决策者知道哪些是政策性问题。**多久一次**——每两个月一次，单月上旬发出。**多长**——每次一千字左右为限，至多不超过两千字。写不完就分两次，一次着重写几个问题，其余略带几笔。**写什么**——该区军事、政治、土改、整党、经济、宣传文化各项活动的动态，发生的问题和倾向，以及对问题的解决方法；而且"要指出问题或争论之所在"。**军队版另加**——纪律、物质生活、指战员情绪与偏向、技术战术的进退、敌军长短处与士气、政治工作、政策执行、军民关系与各阶层动向。

这套参数背后有三个设计意图：字数上限防止用长文掩盖问题；"必写问题与倾向"防止只报喜；固定频次让汇报变成制度而不是运动。

作者还用对照说明效果：按时请示报告的地区避免了损失；不报告的则"发生了某些不可挽救的、或难以挽救的、或能够挽救但已受了损失的事情"。

## A1 — 应用示例 (Application Example)

### 示例 1: 一九四八年的报告制度
- **类型与来源**: 原书案例（f22；《关于建立报告制度》1948，第4卷 p734-735）
- **问题/输入**: 各战略区各自为政，中央不了解下情，只能事后补救；有的地区"事前不请示、事后不报告"，损失既成才被知道。
- **方法论的使用**: 规定书记亲自动手、两月一次、千字上限、内容清单、单月上旬发出；军队另立政策性报告清单；对不执行的地区点名批评。
- **结论**: 信息的及时性靠制度参数保证，不能靠自觉。
- **结果**: 原文给出对照，说明执行地区避免了损失；具体统计未列。

### 示例 2: 报告变成"五多"之一
- **类型与来源**: 原书案例（c/f26；《解决"五多"问题》1953，第5卷 p936）
- **问题/输入**: 五年后，向下要报告本身成了基层负担——"公文报告表册多"，"报告多不批"。
- **方法论的使用**: 反向使用本 skill——报告制度的每一项参数都要有人负责消费：谁看、看了要做什么。没有消费者的报告要求，就是"五多"。
- **结论**: 报告制度的另一半是"上级必须批"。
- **结果**: 原书要求清理并规定适当制度；执行细节未展开。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 多层级组织里，总部不知道一线在发生什么，出事才知道。
2. 周报/月报流于形式：只报进度数字，不报问题与分歧。
3. 汇报材料越写越长，看完仍不知道"哪里有问题、需要什么支持"。
4. 一线抱怨"上面要的东西太多"，而每个上级部门都觉得自己的要求合理。
5. 需要设计一套远程/分布式团队的同步机制。

### 语言信号 (用户的话里出现这些就应激活)

- "出了事才知道" / "we found out too late"
- "周报没人看" / "status reports go nowhere"
- "只报喜不报忧" / "everything is green"
- "汇报要点什么" / "what should the update contain"
- "信息不对称" / "HQ is blind"

### 与相邻 skill 的区分

- 与 `maoxuan-writing` 的区别：writing 管"这份材料怎么写才有人看"，本 skill 管"多久报、报什么、谁写、多长"；先有制度，再谈文风。
- 与 `maoxuan-diagnose` 的区别：diagnose 用报告里的分布做病灶判断；本 skill 保证报告本身有可用信息。
- 与"OKR 周报"的区别：OKR 周报面向目标进度，本 skill 强制包含"问题、倾向、争论之所在"这类负面信息。

## E — 可执行步骤 (Execution)

**必需输入**：① 组织层级与汇报链；② 当前汇报的频次、篇幅、内容；③ 上级实际会用报告做什么决定。
**缺失时询问**：若上级说不出"看报告要做什么决定"，先解决这一条——没有消费者的报告制度必然退化为形式。

**交付物与完成标准**：一份报告制度（≤1 页）＋一份报告模板（含必填字段）＋一份"上级回应"规则。

1. **定责任人**
   - 完成标准：明确由业务负责人本人撰写，不允许助理代笔；写明"为什么必须本人"。
2. **定频次与时点**
   - 完成标准：固定周期（建议两月一次或按业务节奏），固定发出日；不允许"想起来才报"。
3. **定篇幅上限**
   - 完成标准：给出字数/页数硬上限，并说明超出时如何拆分。
4. **定必填内容**
   - 完成标准：至少包含"动态、问题与倾向、解决方法、争论之所在"四类；缺一项视为未报。
5. **定军队版/专项版**
   - 完成标准：为关键职能（如安全、财务、客户）追加专项清单，每项都能被核对。
6. **定上级回应**
   - 完成标准：规定上级在多长时间内必须给回应（批/不批/需补充），否则视为默认通过——这一条防"报告多不批"。
7. **防形式化**
   - 完成标准：每季度检查一次"报告是否被使用"（有几次因报告改变了决定）；没有使用的字段删掉。
8. **异常通道**
   - 完成标准：规定"重大风险不等周期，立即报"的触发条件与通道。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 扁平小团队（<10 人）：日常同步即可，制度成本高于收益。
- 高度自动化、指标实时可见的业务：用仪表盘替代书面报告。
- 危机处置期间：用短周期口头同步，事后再补书面。

### 作者在书中警告的失败模式

- **事前不请示、事后不报告**（x21）：损失既成才被知道。
- **只报技术性数字，不报政策性问题**：上级无法判断方向。
- **报告无消费者**：变成"五多"之一（f26），基层被压垮。
- **用长文掩盖问题**：字数上限正是为此设置。

### 作者的盲点 / 时代局限

- 该制度设计于战争年代的电报条件，信息传输成本极高，因此强调"短"；今天的约束变成"注意力"，原则仍成立但参数需重设。
- 原文预设上级有能力且有意愿处理下情；若上级本身官僚化，报告制度会变成单向的自我证明。
- 未讨论激励问题：报忧者是否会被惩罚。若不解决，制度必然退化为只报喜。

### 容易混淆的邻近方法论

- 与"管理仪表盘"不同：仪表盘给数字，本 skill 要求判断、倾向与争论。
- 与"复盘（postmortem）"不同：复盘面向已发生事件，本 skill 面向持续状态。
